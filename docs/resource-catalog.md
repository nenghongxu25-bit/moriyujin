# 项目资源导航与包体优化

## 先找正式游戏资源

场景、预制体和运行时配置引用的正式资源统一放在 `assets/`。按用途找：

| 资源 | 目录 |
| --- | --- |
| 场景与预制体 | `assets/scenes/`、`assets/prefab/` |
| 地图瓦片、地形和建筑材质 | `assets/tileset/<地图或类别>/` |
| 静态场景装饰 | `assets/decorate/<类别>/` |
| 动画帧和天气特效 | `assets/animation/<类别>/` |
| 物品图标 | `assets/atlas/picture/items/<类别>/` |
| Spine 角色及导出贴图 | `assets/spine/<角色或类别>/` |
| 音乐和音效 | `assets/sound/bgm/`、`assets/sound/sfx/` |
| 物品、掉落和玩法配置 | `assets/config/` |
| 游戏界面图片 | `assets/ui/`、`assets/atlas/picture/` |

更细的图片分类约定见 `docs/image-material-layout.md`。判断资源是否在用时，以场景、预制体、配置中的 UUID 和路径引用为准；文件名或文件夹名本身不能证明它是当前版本。

## 项目根目录中的素材区

| 目录 | 用途 | 是否作为运行时资源 |
| --- | --- | --- |
| `art/` | 制作原稿、拆分图层、生成过程版本；部分工具和预览页面会按路径读取 | 否，除非某工具明确引用 |
| `art-library/` | 备用素材、预览和美术参考 | 否 |
| `backups/`、`.tmp/` | 可恢复的改动备份、检查截图和临时处理结果 | 否 |
| `archives/` | 已归档的历史项目文件 | 否 |
| `release/` | 按发布平台生成的构建产物 | 生成目录，不作为源资源编辑 |
| `assets/` | 当前 Laya 工程资源 | 是，具体资源由工程引用和构建设置决定 |

不要因为看到相同主题或相近文件名就移动、覆盖或删除素材。改动 `assets/` 内的路径时，要同时更新 UUID 元数据、场景/预制体引用及读取该路径的工具。

## 图集和压缩

把多个小图拼成图集通常能减少纹理切换和绘制批次，对性能有帮助；图集本身不保证下载包变小。图集会增加透明边距、对齐留白，若原始单图仍一并发布，包体还可能增大。当前 `assets/atlas/picture/` 是图片分类目录，目录名里的 `atlas` 不代表这些图片已经打成运行时图集。

适合评估图集：同屏频繁出现、尺寸较小、材质设置一致的 UI 图标或小型特效帧。地图瓦片、重复平铺纹理、Spine 导出页和大型单体立绘应使用各自现有的图集/导出规范，不要混进通用 UI 图集。

压缩优先顺序：

1. 对最终发布包内的大 PNG 做无损优化，保持路径、UUID 和像素尺寸。
2. 对可接受轻微画质损失的静态图片制作候选 WebP/量化 PNG，目视对比后再接入，并核对 Web、字节小游戏等目标平台的解码支持。
3. 对声音检查编码码率、采样率和是否存在重复内容；音乐目前约 14 MiB 的工程源文件总量，需按实际发布引用评估。
4. 根据场景和构建设置确认未引用资源是否进入发布包；优先调整构建包含项，不做未经确认的资源删除。

图集优先解决运行时批次和加载管理；要降低下载体积，应单独测量纹理压缩、分辨率、编码格式和构建结果。
