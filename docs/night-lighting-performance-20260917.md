# NightMask 诊断与 A/B 测试（2026-09-17）

## 结论

只完成诊断，没有应用性能优化或改变正式视觉参数。

- 稳定静止时，平滑开/关都是约 60 FPS、0 次 reCache 请求/秒。
- 移动时，开平滑 51.4–55.7 FPS，关平滑 59.8–60.0 FPS。请求次数从逐帧降至约 0.66 次/秒。
- 持续瞄准、移动加瞄准时，开/关平滑均逐帧刷新，均存在明显慢帧。单纯关闭平滑不能解决这两类场景。
- 发现了额外的运行时证据：旋转时缓存 RenderTexture 尺寸几乎逐帧变化，最大约 1752×1752；这不是 512×512 源 PNG 的尺寸。
- 这些结果支持“移动平滑增加缓存更新开销”，但不证明 reCache 方法本身是唯一瓶颈，也不构成删掉 bitmap 缓存的依据。

## 方法

在本机 Laya 编辑器运行 city.ls。设计尺寸 1334×750，测试记录的浏览器内容区域 906×510。
每种场景采用 A（原平滑）/B（关闭平滑）/B/A 顺序，各预热 2 秒、采样至少 6 秒，总计 16 段。
平滑开启参数：positionSmoothTime=0.025，directionSmoothTime=0.045；关闭时仅将这两个参数设为 0。
素材、缓存模式、Sprite 数量、光束尺寸、渐变、混合模式均相同。

临时工具每帧写入现有 Joystick 的轴值和 attack 的静态瞄准方向：

- 静止：移动和瞄准输入均为零。
- 移动：水平往返，每 1.5 秒换向，经过原玩家移动、碰撞、动画和相机逻辑。
- 瞄准：站立，方向以每秒 60° 连续旋转。
- 移动加瞄准：同时应用上述两种输入。

没有模拟开火，也没有合成真实触摸事件；这是实际游戏渲染中的受控输入回放，不是纯数学模拟。
每段重置玩家位置，并保留 2 秒预热。移动段记录的玩家位移范围约 300–317 世界像素，稳定静止/瞄准段位移为零。

## 指标含义和代码证据

- reCache：只统计当前 nightlayer 实例的显式方法调用，不等于全部引擎自动失效次数或实际 GPU pass 次数。
- rtChecks：该实例 updateRenderTexture 的调用次数。
- rtChanges：该方法返回 true 的次数。已核对本地引擎：尺寸相同时复用现有 RT 并返回 false；尺寸改变时回收旧 RT、从池获取对应尺寸 RT 并返回 true。**不等于每次都新建 GPU 纹理**。
- maxRT：该方法执行时观察到的最大宽、高。静止段的 [0,0] 表示没有发生尺寸检查，不表示实际 RT 大小为零。
- 帧间隔来自 performance.now() 在每帧计时器回调之间的差值；包括渲染/调度影响，不是 GPU 时间。
- render2DCpuMs 仅包围 stage._render2d 的 CPU 提交时间，不能覆盖异步 GPU 执行、浏览器合成、所有 endFrame 成本。未据此推断 GPU/GC 的具体占比。

项目路径：src/debug/DynamicCutoutProbe.ts，changed 分支调用 owner.reCache；configureCache 设置 bitmap。
本地引擎 laya.core.js 中 reCache 调用 repaint；updateRenderTexture 使用子树边界决定 RT 尺寸。
两个光照 Sprite 的宽高约 1238.71×1238.71，旋转后轴对齐边界可达到约 1752×1752，符合运行时观测。
