# 物资图片与容器动画制作规范

根据本次物资点制作及旅行箱、旅行袋等返修整理。后续制作先读本文，再沿用现有工具和资源结构。

刚性箱盖、柜门和纸箱折盖的具体操作、参数定义、重建命令及交付门槛，统一以 [可照抄操作单](rigid-container-animation-recipe.md) 为入口。它补充了第四批反复遮罩修补失败后实际采用的完整主体与固定部件方法。

## 1. 先定规格，再画图

先列清单：ID、中文名、用途、占格宽高、收起/展开状态、朝向、画布尺寸；容器另记地图显示尺寸、落地点、固定主体、活动部件及铰链位置。

| 用途 | 交付规格 | 注意事项 |
| --- | --- | --- |
| 背包物资图标 | 每格 256×256；宽高按占格计算 | 1×2 为 256×512，2×1 为 512×256，2×2 为 512×512 |
| 收起/展开的背包与弹挂图标 | 两个状态各自按外部占格输出 | 内部容量和分隔布局属于数据，不能用内部容量推算图标尺寸 |
| 当前地图容器动画 | 每帧 512×512，4 帧，8 fps，不循环 | 地图显示大小由配置决定，不套用背包每格 256 的规则 |

物体等比缩放、不拉伸；透明背景；稀有度底色由 UI 绘制，不烘焙在图案里。同批统一观察角度、光照、材质细节和视觉尺度。参考已有项目素材，避免每批改变画风。

## 2. 容器动画从固定主体制作

**先做好一件容器及其部件，再制作动作。不能把四张独立生成的整物图直接当成稳定动画。**

推荐分层：固定箱体（含内部）、前沿遮挡层、盖子外侧、盖子内侧；拉链包则为固定包体和局部包口。先确认关闭和完全打开两端，再补中间帧。

- 硬箱、旅行箱、垃圾桶：固定箱体，只让盖子绕同一铰链转动。
- 机箱、柜子：固定主体，只变换侧板或门；遮挡关系按该物件单独检查。
- 帆布袋：固定包底、侧面、提手，仅替换包口区域。检查遮罩接缝，避免残留旧包口或切断新包口。
- 中间帧优先复用已有层，通过投影/变换制作。现有仿射投影适合本批简短风格化动作，复杂透视、软布变形和连杆不能保证直接适用，需要单独设计。
- 绘制顺序通常为箱体、活动盖面、前沿遮挡；不要让盖子穿过前壁。
- 所有帧共用画布、主体尺度、落地点和锚点。预留完全打开时所需空间，不按每帧可见内容重新缩放或居中。

新素材的生成说明应明确：固定镜头和主体比例、各部件完整、不裁切盖子及提手、透明背景、无文字/水印/额外小物。提示词只能降低偏差，不能替代尺寸和分层验收。

## 3. 本次错误及对应处理

| 问题 | 原因/限制 | 下次做法 |
| --- | --- | --- |
| 打开时忽大忽小 | 独立生成帧的箱体形状本来就不同；逐帧按包围盒缩放又放大差异 | 共用固定主体，活动部件独立制作；配准只做辅助 |
| 位置对齐后仍在抖动 | 平移、缩放不能修正局部形变 | 对比箱角、底边、锁扣、提手等固定部位，不只比较画布尺寸 |
| 提手/箱盖被截断或串入邻图 | 实际源图尺寸与预期不符，且部件跨越四宫格边界 | 读取实际尺寸，逐格检查完整轮廓；越界时重取样或单独取部件，不能盲目四等分 |
| 空白处出现碎片 | 原帧透明区域残留、旧图层未完全清除或遮罩范围不完整 | 在源图、分层合成后分别检查透明区域，清理无关连通块并检查接缝 |
| 图标和格子比例不匹配 | 先画统一方图，后补占格数据 | 先定占格，再按比例构图和导出 |
| 文件修改后仍看到旧图 | 已运行预览可能保留旧纹理 | 停止并重新运行预览，确认读到新资源；不能把实际缺陷归咎于缓存 |

透明清理不要一律只保留最大连通块：独立提手、肩带、盖子和细小附件可能是有效内容。本次旅行袋适合按连通轮廓清理并保留一像素低透明度抗锯齿边缘；其他物件要先核对结构。

## 4. 更快的批量流程

1. 列规格和复用关系：同形状的等级装备复用立绘，颜色由 UI 区分；确实需要不同造型的弹挂等才分别绘制。
2. 每种新开合结构先完成一个样件的整条流程：绘制、分层、四帧、实际显示尺寸预览、项目内播放。样件检查通过后再做同类批次。
3. 保留原图，建立活动层和固定层；优先复用已有脚本，仅补该物件的遮罩、源三角形、铰链和运动参数。不要为了小瑕疵重生成整批。
4. 一次导出同一物件的全部帧，按清单检查尺寸、透明度、命名和帧顺序；先看四帧并排，再循环播放。
5. 接入原项目路径、配置和预制体，保留 UUID。交付包括项目内可用资源及明确预览入口，不能只留下展示图片。
6. 修改哪个物件就重建哪个物件；完成相关验证后停止重复处理。留存备份和检查结果，避免再次覆盖已修好的版本。

## 5. 必须通过的检查

- 静态：实际 PNG 尺寸符合用途，物体等比，四边无裁切，透明区域没有邻图残片。
- 透明背景：在浅色、深色、棋盘格背景检查四帧，兼看原尺寸及游戏显示尺寸；黑底上看不见的暗色残留也要检查。
- 动态：逐帧和循环检查固定主体、落地点、盖子铰链、遮挡、接缝、附件完整性。正常的开盖外轮廓变化不能误当成箱体缩放。
- 固定区域：比较应保持不动且未被活动部件遮挡的像素。不能只对比整个图的外接矩形，也不能用通过局部像素检查替代动画目视检查。
- 项目内：资源加载成功、帧序和速度正确、结束停在打开状态、预制体显示比例合适。涉及 Laya 运行问题先读取 MCP 运行状态，再做针对性检查。

## 6. 当前可复用文件

| 路径 | 用途与边界 |
| --- | --- |
| `tools/test-loot-icon-sizes.cjs` | 背包图标尺寸核对 |
| `tools/lock-weapon-crate-body.ps1` | 军用武器箱固定箱体及盖面投影 |
| `tools/lock-container-bodies.ps1` | 已配置的八种容器；新增物件需添加专用参数，不能直接套用别的物件坐标 |
| `tools/stabilize-loot-frames.ps1` | 旧帧配准辅助；不能解决生成帧的局部形变，已保护固定主体修正版 |
| `tools/install-loot-point-art.ps1` | 初始切片工具；输入必须先检查，不能覆盖已修正帧 |
| `tools/build-fixed-container-preview.cjs` | 固定主体修改前后预览；当前检查八条记录，增加数量时需同步更新 |
| `tools/test-loot-point-ui.cjs` | 已配置批次的项目播放检查；依赖现有浏览器调试服务，新增批次需检查测试假设 |
| `art/container-bodies-before-lock/` | 本轮修正前备份 |
| `art/container-fixed-layers/` | 已分离的固定主体、盖面等图层 |
| `assets/scenes/loot-points-all.ls` | 项目内物资点总览入口 |

单件重建示例（在项目根目录执行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/lock-container-bodies.ps1 -Only suitcase
node tools/build-fixed-container-preview.cjs
node tools/test-loot-point-ui.cjs --batch2
```

这些命令是现有工程的复用入口，不是任意新容器的一键生成器。图像生成仅用于需要新绘制或重绘的素材；常规分层、投影、导出沿用项目工具，按当前工具约束执行。
