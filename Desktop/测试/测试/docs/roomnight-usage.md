# 房间黑暗与开灯

修改前备份：`D:/Desktop/测试/backups/roomnight-20260917-113212`。

## 编辑器设置

- `Area2D/roomnight` 保持在 Nightlayer 后面、UI 前面。现有位置和两个矩形的尺寸均保留。
- 调整 `roomnight` 下 `Sprite`、`Sprite_1` 的位置和大小，使黑色矩形覆盖对应室内地面。它们同时是进入房间的检测区域。
- 每个矩形的 `RoomNightZone` 组件中，“房间开灯”控制该房间夜间是否亮着。
- `roomnight` 的 `RoomNightController` 中，“夜晚”切换昼夜。天气系统以后通过该组件的 `isNight` 属性接入，目前是手动开关。
- 两个矩形默认独立。如果它们其实属于同一间屋子，勾选“所有区域属于同一房间”，进入任一区域会一起显示。
- Nightlayer 下的 `room_light_cutout_lower/upper` 是已绑定的夜色扣除节点，运行时自动定位，不需要手动摆放。
- “运行房间回归测试”默认关闭；它会移动玩家，只用于测试。

## 显示规则

| 玩家状态 | 效果 |
| --- | --- |
| 室外 | 房间保持黑色遮挡，开灯也不会泄露室内 |
| 白天进入 | 整个对应房间遮挡淡出 |
| 夜晚进入、关灯 | 房间遮挡淡出，但保留全局夜色和手电 |
| 夜晚进入、开灯 | 房间遮挡淡出，并扣除该区域全局夜色；室外仍黑 |
| 离开房间 | 恢复室内遮挡 |

UI 不参与上述遮罩。进入判断使用玩家节点原点，边界有 6 像素退出缓冲，淡变默认 0.12 秒。

## 实现与验证

复用场景矩形和现有 bitmap 夜色合成，不引入真实灯光、Blur 或额外全屏 RenderTexture。坐标临时对象复用；房间位置变化时只调整已有扣除节点。动态扣除仍可能请求现有夜色缓存重绘，不代表完全没有每帧渲染成本。

通过 Laya MCP 实际运行了 9 项用例：白天室外、白天室内、夜晚关灯、夜晚开灯、离开、第二个房间、合并房间、亮房间移动、亮房间边缘。全部状态与对齐断言通过，截图确认室内亮、室外暗及 UI 正常。

前 8 项前台短时采样约 60 FPS，夜间 RenderTexture 尺寸保持 3000×3000、没有尺寸变化。该尺寸来自当前已有手电范围，没有修改用户的手电尺寸。最后边缘用例采样期间窗口进入后台，其 FPS 不作为性能结论。此结果不代表目标手机性能测试。

原始记录见 `roomnight-regression-20260917.raw.json`。原始 FPS 统计包含起始帧，有约 0.5 FPS 的计数偏差，记录保留原样；诊断脚本已修正后续统计。
